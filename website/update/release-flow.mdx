本文记录 YumeBox MD3 的正式发布、预发布、更新封面处理，以及 `website/update/update.json` 的维护方式。后续更新验证直接走 GitHub 上的 `update.json` 和 Release APK，不再维护本地网页调试链路。

## 先记住

构建 release APK 之前一定先做这三步：

1. 先按指令跑一个update.json出来再提交最终源码。
2. 运行 native 构建，让核心版本信息基于当前 commit 生成。
3. 再运行 `.\gradlew.bat :app:assembleRelease`。

原因是 native bridge 会读取当前 Git commit hash 写入核心版本信息。如果先构建 native、后提交，关于页里的 native hash 会落后于真正发布的提交。发布前重构 native 推荐显式跑 Go、Rust、C++；Geo 资源只有显式传 `--geo` 时才会下载。

正式发布和预发布走不同分支：

```text
stable:  Yume/website/update/update.json
preview: Dev/website/update/update.json
```

App 读取的是 raw 文件，不是 GitHub 目录页面：

```text
stable:  https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json
preview: https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Dev/website/update/update.json
```

GitHub Release 上传的 APK 文件名固定为：

```text
YumeBoxMD3-release.apk
```

App 会根据 `releaseUrl` 和 `tag` 拼出下载地址：

```text
https://github.com/Yizuka17/YumeBox-MaterialDesign/releases/download/v0.5.4/YumeBoxMD3-release.apk
```

## update.json

远端 `update.json` 只保留更新判断、展示和下载入口需要的字段：

```json
{
  "manifestUrl": "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json",
  "channel": "stable",
  "tag": "v0.5.5",
  "versionName": "0.5.5",
  "versionCode": 5500,
  "releaseNotes": "更新说明",
  "releaseUrl": "https://github.com/Yizuka17/YumeBox-MaterialDesign/releases/tag/v0.5.5",
  "coverUrl": "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/release-cover-v0.5.5.webp",
  "coverDataUri": "data:image/webp;base64,..."
}
```

这些字段会在弹窗中展示：

- `versionName`：远端版本名。
- `tag`：GitHub Release tag。
- `releaseNotes`：更新说明。
- `coverUrl` / `coverDataUri`：更新封面。

这些字段用于更新判断和下载：

- `versionCode`：判断是否有更新，必须大于当前 App。
- `releaseUrl`：GitHub Release 页面。
- `manifestUrl`：当前清单 raw 地址，方便核对 App 正在读哪里。
- `channel`：`stable` 或 `preview`。

不再写 `packages`、`downloadUrl`、`size`、`sha256`。APK 下载地址由 App 根据 `releaseUrl + tag + YumeBoxMD3-release.apk` 生成。

## 发布前检查

- `gradle.properties` 中版本号已更新：

```properties
project.version.name=0.5.5
project.version.code=5500
```

- `versionCode` 必须大于线上版本。
- release 签名配置可用。
- GitHub Release 的 tag 与 `update.json.tag` 一致。
- Release asset 名称是 `YumeBoxMD3-release.apk`。
- 如果本次要展示更新封面，本机有 WebP 编码器：

```powershell
winget install --id Google.Libwebp --accept-source-agreements --accept-package-agreements
cwebp -version
```

## 正式发布

正式发布在 `Yume` 分支构建，App 默认读取：

```text
https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json
```

推荐顺序：

1. 切到 `Yume` 分支。
2. 更新版本号、更新说明、封面资源。
3. 提交最终源码。
4. 运行 native 构建：

```powershell
kotlin scripts/native-build.main.kts --go --rust --cpp
```

5. 如果 native 产物需要入库，提交 native 产物。
6. 构建 release APK：

```powershell
.\gradlew.bat :app:assembleRelease
```

7. 检查生成结果：

```text
app/build/outputs/apk/release/YumeBoxMD3-release.apk
website/update/update.json
```

8. 创建 GitHub Release，上传 `YumeBoxMD3-release.apk`。
9. 推送 `website/update/update.json` 和封面到 `Yume` 分支。
10. 浏览器打开 raw `update.json` 验证内容。
11. 真机点击「检查更新」验证弹窗、封面、下载、取消下载和安装器拉起。

`assembleRelease` 只生成 APK，不会生成或覆盖 `update.json`。`update.json` 需要单独生成：

```powershell
.\scripts\generate-update-manifest.ps1 `
  -Apk "app\build\outputs\apk\release\YumeBoxMD3-release.apk" `
  -Tag "v0.5.5" `
  -VersionName "0.5.5" `
  -VersionCode 5500 `
  -Channel "stable" `
  -ManifestUrl "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json" `
  -ReleaseNotes "这里填写更新说明" `
  -CoverUrl "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/release-cover-v0.5.5.webp" `
  -CoverDataUriFile "build\update-assets\release-cover.data-uri.txt" `
  -Output "website\update\update.json"
```

写进 APK 的发布信息可以临时写进本机 `signing.properties`，不要提交：

```properties
update.channel=stable
update.manifestUrl=https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json
```

## 预发布

预发布在本地 `Dev` 修改基础上构建，App 读取：

```text
https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Dev/website/update/update.json
```

预发布写进 APK 的发布信息可以临时写进本机 `signing.properties`，不要提交：

```properties
update.channel=preview
update.manifestUrl=https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Dev/website/update/update.json
```

然后同样运行：

```powershell
.\gradlew.bat :app:assembleRelease
```

生成后上传 `YumeBoxMD3-release.apk` 到对应 prerelease，再推送 `website/update/update.json` 到 `Dev` 分支。

预发布 `update.json` 同样单独生成：

```powershell
.\scripts\generate-update-manifest.ps1 `
  -Apk "app\build\outputs\apk\release\YumeBoxMD3-release.apk" `
  -Tag "v0.5.5-pre.1" `
  -VersionName "0.5.5-pre.1" `
  -VersionCode 5501 `
  -Channel "preview" `
  -ManifestUrl "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Dev/website/update/update.json" `
  -ReleaseNotes "这里填写预发布说明" `
  -CoverUrl "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Dev/website/update/release-cover-v0.5.5-pre.1.webp" `
  -CoverDataUriFile "build\update-assets\release-cover.data-uri.txt" `
  -Output "website\update\update.json"
```

注意 GitHub 的 `releases/latest` 不会指向 prerelease；预发布不要依赖 latest。

## 更新配置

写进 APK 的 Gradle 指令：

```powershell
"-Pupdate.channel=stable"
"-Pupdate.manifestUrl=https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json"
"-Pupdate.manifestMirrorTemplates=https://mirror.example.com/{url}"
"-Pupdate.mirrorTemplates=https://mirror.example.com/{url}"
"-Pupdate.releaseApkFileName=YumeBoxMD3-release.apk"
```

这些值也可以写进本机 `signing.properties`，不要提交。`manifestUrl` 是 App 去哪里找清单；`mirrorTemplates` 是下载清单和 APK 时的镜像兜底；`releaseApkFileName` 是 release APK 输出文件名。

生成 `update.json` 的脚本参数：

```powershell
.\scripts\generate-update-manifest.ps1 `
  -Apk "app\build\outputs\apk\release\YumeBoxMD3-release.apk" `
  -Tag "v0.5.5" `
  -VersionName "0.5.5" `
  -VersionCode 5500 `
  -Channel "stable" `
  -ManifestUrl "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/update.json" `
  -ReleaseNotes "这里填写更新说明" `
  -CoverUrl "https://raw.githubusercontent.com/Yizuka17/YumeBox-MaterialDesign/Yume/website/update/release-cover-v0.5.5.webp" `
  -CoverDataUriFile "build\update-assets\release-cover.data-uri.txt" `
  -Output "website\update\update.json"
```

一句话区分：Gradle 只负责 APK 内置的清单入口和 APK 文件名；`generate-update-manifest.ps1` 负责 `tag`、`releaseUrl`、版本、更新说明和图片字段。

## Debug 真机安装

只验证 App 侧更新弹窗、自动检查、封面预加载、下载取消等逻辑时，不覆盖版本号，直接构建 debug：

```powershell
.\gradlew.bat :app:assembleDebug --no-configuration-cache
```

确认设备：

```powershell
adb devices
adb shell getprop ro.product.cpu.abi
```

按设备 ABI 安装对应 APK，例如 arm64：

```powershell
adb install -r "app\build\outputs\apk\debug\YumeBox-arm64-v8a-debug.apk"
```

## 更新封面

推荐把封面源图和 WebP 都放在 `website/update/`：

```text
website/update/release-cover-v0.5.5-source.jpg
website/update/release-cover-v0.5.5.webp
```

生成 WebP 和 Base64 兜底：

```powershell
.\scripts\convert-image-to-base64.ps1 `
  -Input "website\update\release-cover-v0.5.5-source.jpg" `
  -Output "build\update-assets\release-cover.data-uri.txt" `
  -EncodedImageOutput "website\update\release-cover-v0.5.5.webp" `
  -Format webp `
  -MaxWidth 1280 `
  -MaxHeight 720 `
  -Quality 82
```

App 优先加载 `coverUrl`；如果 URL 图片失败，并且 `coverDataUri` 不为空，再使用 Base64 兜底。Base64 会让 `update.json` 变大，因此不要直接塞原图。

## 常见问题

### 检查更新显示已经是最新版本

确认 `update.json.versionCode` 大于已安装 App 的 `versionCode`。

### 更新弹窗出来了但下载失败

确认 GitHub Release 已发布，并且以下地址可直接下载：

```text
https://github.com/Yizuka17/YumeBox-MaterialDesign/releases/download/<tag>/YumeBoxMD3-release.apk
```

### 下载后安装失败

常见原因：

- 新 APK `versionCode` 没有高于已安装版本。
- APK 签名与已安装包不一致。
- `applicationId` 不一致。
- 下载的 Release asset 不是同一个应用包。
